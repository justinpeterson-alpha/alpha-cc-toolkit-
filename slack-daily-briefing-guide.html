Build Your Own Daily Slack Briefing

A copy-paste template for setting up an automated daily Slack briefing — the same one running for Alpha Miami's Campus Coordinator. It reads a fixed set of channels plus your DMs, and delivers a to-do-first summary every morning.

⏱ ~10 min setup 🧩 No coding required 🔌 Requires Slack connected to Claude

1Schedule

Runs once a day as a scheduled task (not a live chat), covering the previous calendar day. Pick one fixed time zone up front — every date filter depends on it.

2Source

Your own DM history, plus 3–5 channels that matter to your role: one high-traffic team channel, one site-specific channel, one requests/tickets channel, one org-wide announcements channel.

For each channel, two passes run: pull new top-level messages in the date window, and separately check for threads that got new replies in that window — even if the parent message is older. That second pass is what catches replies to older threads the first pass alone would miss.

3Filtering logic

Include: urgent or actionable items, anything @-mentioning you, threads with 5+ replies, and corrections to previously shared info.

Skip: routine chatter that resolved cleanly, and duplicate automated notices.

When unsure, include it with a short note rather than dropping it.

4Output format

A consolidated "Today's To-Do List" at the top (Urgent / Regular, tagged by source), then one section per channel, always in the same order. Short bullets, Slack-native bold/italic formatting — no Markdown headers, since those don't render in Slack. Roughly 500–800 words total.

5Delivery

Parent message posted to your own self-DM, then one threaded reply per section underneath it.

Sample output

What a finished briefing actually looks like (fake data):

Today's To-Do List
Urgent: Follow up with J. Smith re: a student pickup mix-up [DM] · Confirm vendor callback on HVAC repair, due today [#requests]
Regular: RSVP count for Friday assembly [#announce] 1. DMs 4 threads — mostly resolved, 1 open ask above. 2. #team-channel Quiet day; one 6-reply thread on early-dismissal policy — no single answer yet, worth flagging. 3. #requests 2 new tickets, both facilities-related.

What you'll need

  • A Claude account with Slack connected
  • Optional: Gmail connected too, if you want an email mirror of the briefing
  • No coding — you're filling in a text template and asking Claude to schedule it

Step 1 — Fill in your placeholders

PlaceholderWhat it isHow to find it
{YOUR_TIMEZONE}Your local time zonee.g. "America/New_York"
{YOUR_USER_ID}Your Slack user IDAsk Claude: "what's my Slack user ID?"
{YOUR_DM_CHANNEL_ID}Your self-DM channel IDAsk Claude: "what's the channel ID for my self-DM?"
{CHANNEL_1} … {CHANNEL_4}The channel names to covere.g. #campuscoordinators, #your-site-name, #requests-for-cc, #org-wide-announce
{YOUR_EMAIL}Your email (optional)For an optional Gmail mirror of the briefing

Step 2 — Create the scheduled task

Tell Claude: "Set up a scheduled task with this prompt, running every weekday morning at [TIME] in {YOUR_TIMEZONE}" — then paste the block below with your placeholders filled in.

You are generating my daily Slack briefing, covering the previous calendar day (yesterday 12:00 AM to 11:59 PM, {YOUR_TIMEZONE}). DATA COLLECTION — use a two-pass approach for every channel below: Pass 1: Pull new top-level messages posted during the window. Pass 2: Separately check for threads that received NEW REPLIES during the window, even if the parent message is older than the window. Produce a report with these sections, in order: 1. PRIVATE DMs — summarize DMs received/sent in the window; build a to-do list of anything needing a response; ignore my own self-DM thread. 2. {CHANNEL_1} — separate signal from noise; call out urgent to-dos, regular to-dos, then updates/corrections; flag threads with 5+ replies. 3. {CHANNEL_2} — note anything directed at me (@mentions); summarize the day's discussion; note what people are asking for. 4. {CHANNEL_3} — summarize requests from staff; build a to-do list; flag patterns (repeat requesters, recurring issues, unresolved items). 5. {CHANNEL_4} — summarize discussion including thread-only activity; separate urgent from general; flag recurring issues across days. FORMAT: - Consolidate all to-dos into one "Today's To-Do List" at the top, split into Urgent and Regular, tagged by source channel/DM. - Carry forward unresolved prior-day items ONLY if their deadline is today or tomorrow, labeled as carryovers. - If a channel had zero activity, state that plainly. - Use Slack markdown (*bold*, _italic_, bullets) — not Markdown headers. DELIVERY: 1. Post to my Slack self-DM (user ID {YOUR_USER_ID}, channel {YOUR_DM_CHANNEL_ID}) using slack_send_message. Post the header + to-do list as the parent message, then each section as a threaded reply (thread_ts = the parent's message_ts). 2. Optional: also create a Gmail draft to {YOUR_EMAIL} with subject "Slack Daily Briefing – [date]" containing the same report as HTML.
⚠️ Heads up: the placeholders above are highlighted for readability. When you copy the block, copy the plain text underneath — Claude will read {CHANNEL_1} etc. as literal text to replace, not as code.

Step 3 — Test it

Ask Claude to run the task once manually before trusting the schedule, so you can adjust which channels are noisy vs. worth including.
