Build Your Own Daily Gmail Briefing

A copy-paste template for an automated daily Gmail briefing. It scans your inbox and sent mail for what actually needs a response, filters out the noise, and leaves a ready-to-read draft waiting every morning.

⏱ ~10 min setup 🧩 No coding required 🔌 Requires Gmail connected to Claude

Setup steps

1

Pick your delivery

Decide if you want the briefing as a Gmail draft only, or a Gmail draft plus a Slack DM to yourself. The template below includes both — delete the Slack paragraph if you only want the draft.

2

Fill in every placeholder

Anything in [BRACKETS] in the template. These are the only parts you need to change.

3

Pick a time and time zone

Decide when it should run each day (e.g. "7:15am Eastern, weekdays only"). Mornings work best since it summarizes the previous calendar day.

4

Ask Claude to create the scheduled task

Paste the filled-in template and say: "Create a scheduled task that runs this every [FREQUENCY] at [TIME] in [TIME ZONE], using this exact prompt: [paste template]." Claude will confirm the schedule and whether it needs your approval on each run.

5

Test it once before trusting it

Ask Claude to fire the task immediately as a manual test run, so you can see the output and adjust wording before it runs unattended.

6

Tune after the first real run

Loosen or tighten the filtering rules, add or remove sections, and rename categories to match how your role actually works.

What it filters

Covers: real mail only — anything you'd actually reply to, plus both new threads and older threads that got a new message during the window. Sent mail is checked too, so the briefing reflects what you owe a reply to as well as what's owed to you.

Excludes: newsletters, marketing, and automated notifications (no-reply senders, delivery receipts, content-free calendar invites, file-share notices) — with one exception: an automated message is kept if it has a real deadline, a security or access alert, an invoice or payment issue, or something requiring action.

Sample output

What a finished briefing looks like (illustrative, not real inbox data):

Today's To-Do List
Urgent: Reply to district office re: field trip permission deadline [Needs a reply] · Approve the substitute request for Thursday [Deadlines]
Regular: Circle back with the caterer on Friday's order [Awaiting someone else] 1. Needs a reply from me District office, field trip permission slips — asked Tuesday, no reply yet. 2. Awaiting someone else Caterer hasn't confirmed Friday's headcount, asked 2 days ago. 3. Deadlines, dates & commitments Substitute approval due end of day tomorrow. 4. Section names in your version will match whatever ops/people categories you set in the template.

Step 1 — Fill in the template

Copy the block below, replace every [BRACKET], then hand it to Claude as instructed above.

You are generating my daily GMAIL briefing, covering the previous calendar day (yesterday 12:00 AM to 11:59 PM, [TIME ZONE]). I am [YOUR NAME], [YOUR TITLE] at [YOUR ORGANIZATION/CAMPUS] ([YOUR EMAIL]). [OPTIONAL: This is a companion to my [OTHER BRIEFING NAME], a separate scheduled task that runs at [TIME]. Do not re-summarize that content here.] DATA COLLECTION Use the Gmail connector. Search threads received or sent during the window. Two passes: (1) new threads that started during the window, (2) older threads that got a NEW message during the window — read those too, don't assume a quiet day just because few new threads started. Also check my Sent mail so the briefing reflects what I said I'd do and what I'm owed a reply on. SIGNAL FILTERING Cover real mail only. Exclude newsletters, marketing, automated notifications (no-reply senders, delivery receipts, content-free calendar invites, file-share notices) — anything I'd never reply to. Exception: keep an automated message if it has a real deadline, a security/access alert, an invoice/payment issue, or something requiring my action. Give a one-line filtered count at the end; don't list what was filtered. REPORT STRUCTURE - A 2-3 sentence orientation: what actually mattered. - TODAY'S TO-DO LIST, split Urgent/Regular, each item tagged with its source thread. Carry forward unresolved items from prior days only when their deadline is today or tomorrow, and label them as carryovers. - 1. NEEDS A REPLY FROM ME (who, what, when asked, how long waiting) - 2. AWAITING SOMEONE ELSE (my open asks, how long pending) - 3. DEADLINES, DATES & COMMITMENTS (near-term first) - 4. [YOUR OPS CATEGORY, e.g. "VENDORS, FACILITIES & OPS"] — list your recurring vendor/ops categories here, e.g. [VENDOR A], [IT PROVIDER], [FACILITIES CONTACT] - 5. [YOUR PEOPLE CATEGORY, e.g. "STUDENT & PARENT MATTERS"] — be factual, name specifics (who, what, when), and do not speculate about medical or health matters. - 6. INTERNAL / ORG (must-do vs. FYI) - 7. NOTABLE PATTERNS (repeat senders, recurring issues) If a section is empty, say so plainly rather than skipping it. FORMAT Attribute specifics: name the sender and the time for every item. Never invent detail. If something is ambiguous, say plainly that it's ambiguous rather than guessing. Prioritize actionability over completeness. DELIVERY 1. [OPTIONAL — SLACK] Post to my own Slack DM (user ID [YOUR SLACK USER ID], channel [YOUR DM CHANNEL ID]). Header + orientation + to-do as the parent message; each section as a threaded reply — combine short sections into one reply rather than posting near-empty messages. Use Slack markdown (*bold*, _italic_, • bullets), not markdown headers. Keep each message under the 5000-character limit. 2. Create a Gmail DRAFT to [YOUR EMAIL] with subject "Gmail Daily Briefing – [date]", an HTML body and a plain-text fallback. Write the HTML directly in the htmlBody field — do not wrap it in CDATA tags or any XML wrapper. Leave as a DRAFT — do not send, even if a send tool is available. Confirm delivery and state the filtered-message count when done.
⚠️ Heads up: the placeholders above are highlighted for readability. When you copy the block, copy the plain text underneath — Claude will read [TIME ZONE] etc. as literal text to replace, not as code.
